# Changelog

All notable user-facing changes to RepliMap are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).
RepliMap is pre-1.0: minor versions may reshape commands — deprecations are
always announced with zero-breakage aliases first. Full version history is
visible on [PyPI](https://pypi.org/project/replimap/#history).

---

## [0.6.1] - 2026-10-01

### Added
- Air-gapped activation for the Sovereign plan: `replimap license activate --file <path>` imports a signed license file with zero network calls, and `replimap license machine-id` prints the id to request one (with `--format json`, and a warning when the id comes from the `~/.replimap/.device_id` fallback, which does not survive containers). The file's signature, signing key, expiry, not-before, clock rollback, machine binding and plan are all verified before the license cache is replaced atomically; any failure leaves the existing cache untouched. Files not bound to a machine, and non-Sovereign files, are refused. `license status` shows when a license was activated from a file. See "Air-gapped activation" in `docs/technical-reference.md`.

### Changed
- Plan descriptions (README, `replimap upgrade`, upgrade prompts, `replimap license status`, pricing reference) no longer list features that are not implemented: team seats, custom webhook payloads, custom report author tag, and SSO. The Team plan is described by what it adds: CI mode with blocking checks, the Trust Center report, 10 activated devices and a 14-day offline grace.
- `codify`: Terraform resource names for load balancers, listeners, target groups, auto scaling groups, SQS queues, SNS topics and secrets that have no usable `Name` tag are now derived from the resource name (listeners: `<lb>_<protocol>_<port>`) instead of the whole ARN, so addresses read like `aws_lb_listener.acme_shop_web_https_443` and no longer embed the account id or region. Same-named resources of one type get a short stable suffix. Existing configurations generated earlier will see different resource addresses on regeneration.
- The license cache `~/.replimap/license.json` is now written with mode 0600 (POSIX) and atomically, for online activation too.

### Fixed
- `codify`: the default VPC, default security groups, main route tables and default subnets are skipped again on real scanner output. An earlier pipeline stage removed the fields the default-resource filter relies on, so these AWS-managed defaults were being generated and imported.
- Scan: the KMS, ECS and Secrets Manager scanners no longer depend on each other in a cycle, which could leave task-definition secret references and key edges pointing at placeholder nodes.
- Scan: SQS dead-letter queue edges no longer depend on the order in which queues are scanned.

### Security
- Dependency updates clearing known advisories in runtime dependencies (anyio, urllib3, click).

## [0.6.0] - 2026-10-01

### Added
- Route53 hosted zones and records, ACM certificates and CloudFront distributions are now scanned, linked in the dependency graph (record -> zone, alias/CNAME -> load balancer / CloudFront / S3 website, CloudFront -> certificate and origins, HTTPS listener -> certificate) and generated by `codify` with Terraform references (alias targets, zone ids, certificate ARNs, origin domains) and correct import IDs. The DNS -> CDN -> load balancer -> compute chain is now visible end to end. CloudFront certificates (always `us-east-1`) are found even when scanning another region. Imported/private-CA certificates and the AWS-created apex NS/SOA records are scanned but not generated. New read-only IAM actions are listed in `IAM_POLICY.md`.
- Secrets Manager, SSM Parameter Store and KMS are now scanned (metadata only, read-only; secret and parameter values are never read). Customer-managed KMS keys, KMS aliases and secrets are generated by `codify` (secrets without any `secret_version`; RDS-managed `rds!` secrets are skipped). SSM parameters appear in the dependency graph but are not generated as Terraform. The graph links secrets, SecureString parameters, RDS, EBS, S3, SQS, SNS and CloudWatch log groups to the KMS key that encrypts them. New read-only IAM actions are listed in `IAM_POLICY.md`; RepliMap does not need `secretsmanager:GetSecretValue`, `ssm:GetParameter*` or `kms:Decrypt`.
- ECS clusters/services/task definitions and ECR repositories are now scanned (task definition environment variable values are never stored). Clusters and repositories are generated by `codify`; services and task definitions are graph only. Task definition secret and SSM parameter references resolve to the scanned Secrets Manager / SSM nodes.
- API Gateway (REST v1 and HTTP/WebSocket v2) APIs, stages, custom domains and VPC links are now scanned into the dependency graph (graph only, read-only `apigateway:GET` list calls; API keys and exports are never called). Route53 alias records pointing at an API Gateway custom domain are linked to it; the alias name and zone id stay hardcoded in `codify`.
- Lambda functions and event source mappings and DynamoDB tables are now scanned (function environment variable values are never stored; no code download, `lambda:GetFunction` is never called). Event source mappings and DynamoDB tables are generated by `codify`; Lambda functions are graph only.
- `codify` now emits the KMS key policy on `aws_kms_key` using the read-only `kms:GetKeyPolicy`, so the first plan shows no policy change.
- `--types` accepts the new service names: `route53`, `dns`, `acm`, `cloudfront`, `cdn`, `edge`, `ecs`, `ecr`, `apigateway`, `lambda`, `dynamodb`, `kms`, `secrets`, `secretsmanager`, `ssm`.

### Fixed
- `codify`: tags are now fetched for IAM instance profiles, ElastiCache clusters/subnet groups, DB parameter/subnet groups, load balancer listeners and CloudWatch log groups, and tag lookups for alarms, IAM roles and log groups are rate limited with retry; RDS resources no longer get a synthetic `Name` tag. Missing tags made the first plan strip real tags.
- `codify`: security group inline rules keep source security groups, `self = true` and per-source descriptions; target groups render their attributes (`deregistration_delay`, `slow_start`, stickiness, ...); load balancers render `access_logs`; VPCs/subnets render Amazon-provided IPv6 blocks.
- `codify`: CloudWatch alarm `dimensions` (and metric-math `metric_query`) are rendered; SQS `redrive_policy` is omitted when empty; RDS clusters/instances, DB parameter group `parameter` blocks and ElastiCache snapshot/notification settings are rendered.
- `codify`: `user_data` on instances and launch templates is no longer rendered as a redacted placeholder (applying it would overwrite the real boot script); it is left to AWS with `lifecycle { ignore_changes = [...] }`, merged with `prevent_destroy` in a single lifecycle block. user_data is still redacted at scan time and never stored.
- `codify`: SQS queues with `max_message_size` above 262144 (now allowed by AWS) keep their real value via `ignore_changes`, because the pinned provider (`hashicorp/aws ~> 5.0`) rejects larger values.
- `codify`: Auto Scaling groups whose only termination policy is `Default` no longer render it.
- `codify`: ACM `key_algorithm` is written in the provider's form (`RSA_2048`, `EC_prime256v1`); the API's `RSA-2048` failed `terraform validate`.
- `codify`: references to nodes that were never scanned (phantoms) stay as literal ARNs instead of invalid `aws_unknown.*` references.
- Coverage: Route53 record ids are normalized across scan and state (trailing dot, name case, `\052` wildcard), so state-managed records are no longer reported as unmanaged.
- `deps` no longer calls `lambda:GetFunction` (which returns a code download URL); it uses `lambda:GetFunctionConfiguration`.
- Scans could randomly drop resources when several scanner threads shared the in-memory SQLite connection; access is now serialized.
- `codify`: Route53 alias records to a load balancer keep AWS's `dualstack.` prefix (`"dualstack.${aws_lb.x.dns_name}"`), so the first plan no longer shows an alias change.
- `codify`: ECS clusters now emit `configuration` (execute command KMS key, logging, log configuration; references when the key or log group is scanned) and `service_connect_defaults`, so the first plan no longer removes them.
- `codify`: AWS-reserved `aws:` tags are no longer written to generated Terraform for any resource type (the provider ignores them, so they caused a diff).
- `codify`: launch templates, Auto Scaling groups (including `mixed_instances_policy`, suspended processes, metrics, termination policies, maintenance policy) and instances now render the attributes the real resources have, so the first plan shows imports only. `user_data` is not managed by the generated code (`ignore_changes`): it is redacted at scan time, never emitted, and the generated `lifecycle` block (merged with `prevent_destroy` when present) includes a comment on how to fetch it manually.

- `codify`: Route53 hosted zones with an empty comment now emit `comment = ""`, so the provider default ("Managed by Terraform") no longer causes an update on the first plan.
- `codify`: no codified resource references a graph-only resource type; such values stay hardcoded.
- `codify`: load balancer, target group and listener ARNs that are in the scan now become Terraform references (they were always left hardcoded). ARNs of load balancers that are not in the scan stay hardcoded.
- `codify`: ACM certificates are regional, not global; a certificate on a regional load balancer is no longer dropped when `--primary-region` differs from the scanned region.

### Changed
- **Behaviour change:** `codify` now skips resources owned by a CloudFormation stack (tags `aws:cloudformation:stack-id` / `aws:cloudformation:stack-name`) by default, because importing them makes Terraform and CloudFormation manage the same resource. The summary shows the number skipped; use `--include-cfn-managed` to generate them. They remain in the scan graph, and `--coverage-state` reports them as auto-created instead of actionable.

## [0.5.10] - 2026-09-28

Includes 0.5.9.

### Fixed
- License machine fingerprint no longer depends on the hostname or network MAC address, which fixes a silent downgrade to the free Community plan every time WSL2 restarted (its virtual NIC's MAC changes on each restart). After upgrading, run `replimap license activate <key>` once per machine to rebind under the new fingerprint; the old machine slot is released automatically, so re-activating does not consume an extra seat.
- `residency` crashed on every run against a cached scan.
- `deps` crashed on every run.
- `audit --format json` crashed on every run.
- `analyze -r <region>` was parsed as a report path; `-r` now means region, as on every other command.
- `iam list-compute` accepts the standard `-r` short flag for `--region`.
- `drift-offline` help examples referenced a nonexistent command spelling.

### Changed
- `deps` (Dependency Explorer) is now available on the Pro plan, matching the documentation. Previously it required Team.
- Audit, drift and deps HTML reports are fully self-contained: chart and graph libraries and styles are embedded, so opening a report makes no network requests and works offline/air-gapped.
- `IAM_POLICY.md`: added read-only actions the CLI actually calls (e.g. `cloudwatch:ListTagsForResource`, IAM role/instance-profile listing used by `deps`). `s3:GetObject` is no longer part of the baseline policy; `drift --state-bucket` users add a separate statement scoped to their state object.
- Package metadata now links to the public `RepliMap/replimap-community` repository for source-of-truth docs, issues and changelog.

## [0.4.12 – 0.5.0] - 2026-08-10

_Aggregates several patch releases between 0.4.12 and 0.5.0; see
[PyPI](https://pypi.org/project/replimap/#history) for exact version boundaries._

### Added

- **IaC Coverage** — `replimap codify --coverage-state` / `--coverage-state-dir`
  matches your live account against one or more Terraform state files (local
  paths or `s3://bucket/key`) and reports which resources exist in **none** of
  them. Unmanaged resources are triaged into actionable ClickOps, embedded
  (e.g. EBS volumes owned by an instance), and likely auto-created
  (service-linked roles). Per-type counts and coverage percentage are free;
  the full resource list and `coverage.json` are Pro.
- **Offline license verification** — license entitlements are Ed25519-signed
  and verified locally; no phone-home in the scan path.
- **Pre-flight region validation** — a misspelled region now fails immediately
  with did-you-mean suggestions instead of a raw connection error after
  retries.
- **Resolvable error references** — `replimap explain ERR-EC2-403-A7X9`
  summarizes the local error log (exception, command, reproduction) for any
  runtime error reference the CLI prints.
- **`drift --managed-only`** and managed-first sectioned drift output, so
  managed drift isn't buried under unmanaged inventory on large accounts.

### Changed

- **Drift comparison is free on every tier** — `replimap drift` /
  `drift-offline` no longer require a paid plan (it's experimental and not
  part of any tier); both commands print an honest note that
  `terraform plan` is the better answer for "did what I manage change?",
  and point at IaC Coverage for "what exists in NO state?".
- **Documented tiers are now enforced** — `trust-center` (Team),
  regional audit frameworks `apra_cps234`/`rbnz_bs11`/`nzism` (Sovereign),
  and `remediate` (Pro, same gate as `audit --fix`) previously ran ungated;
  they now match the published feature matrix. `scan --trust-center` on
  lower plans warns and continues the scan without auditing — the scan
  itself never fails.
- **TEAM AWS account limit is now unlimited (fair use)** — matching PRO;
  no account-count-based upgrade trigger remains on any paid plan.
- **Upgrade prompts honesty pass** — upsell panels no longer mention
  unshipped or retired features (PDF exports, drift alerts, retention
  tiers); they list only what the plan actually includes.
- **Self-contained graph HTML** — D3 is inlined and all CDN references are
  removed; the interactive graph renders fully air-gapped, with hierarchical
  VPC/subnet containers, viewport-aware fit, and a collapsible filter panel.
- **Codify honesty pass** — generated output is framed as an *adoption
  starting point* (not "production-ready"); the generated `backend.tf` no
  longer injects `default_tags` that would force a diff on every imported
  resource; the generated README lists exactly the files written.
- **Audit artifacts** land in `~/.replimap/reports/<timestamp>/` by default
  instead of the current working directory, and the browser no longer
  auto-opens (pass `--open`).
- **Outbound-surface cleanup** — every code path that contacted an external
  host (other than AWS and license validation) was removed from the package;
  right-sizing suggestions are now always computed locally.
- **Type-namespaced graph storage** — same-named resources of different types
  no longer overwrite each other; existing graph caches are rebuilt
  automatically on the next command.

### Fixed

- **Per-item retry in parallel scanning** — a transient AWS error can no
  longer silently drop a resource from the scan; exhausted items are reported
  in the scan summary and the cache is marked partial.
- **A failed scan can no longer overwrite a good graph cache** with an empty
  one.
- Interactive MFA prompts in non-interactive environments now produce a clear
  "re-authenticate profile X" message instead of a bare `EOFError`.
- **`prevent_destroy` now actually reaches generated Terraform** for
  protected resources (databases, S3 buckets, KMS keys, etc.) — the
  completion summary's count was correct, but the protection itself wasn't
  making it into the file.
- **Aurora read replicas managed by Application Auto Scaling** are no longer
  generated as importable resources, since their lifecycle belongs to the
  autoscaling policy, not a static import.
- **Resources sharing the same Name tag** (e.g. members of the same cluster)
  no longer get randomly mismatched Terraform block names.

## [0.3.x] - 2026-01

### Added

- `codify` command — Terraform generation with a 13-stage transformation
  pipeline: lifecycle protection, security-group rule splitting,
  secrets-to-variables extraction, hardcoded-ID-to-reference conversion, and
  Terraform 1.5+ import block generation.
- Interactive D3 dependency graph visualization.
- Local scan caching with `--cache`.

### Fixed

- EC2 `root_block_device` handling that could trigger unintended instance
  replacement.
- AWS system tag (`aws:*`) filtering to prevent provider rejection errors.
- Security-group circular dependencies via automatic rule splitting.
